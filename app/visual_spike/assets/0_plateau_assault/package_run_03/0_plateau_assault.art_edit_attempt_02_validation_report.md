## Rejected

- The altitude still does not read as a decisive physical height change. The image remains too close to a colored/painted surface rather than a low field, cliff face, raised plateau, and sloped access routes.
- The tree/fire feature is still in the wrong place relative to the authored orange footprint.
- The cover count is wrong: the grid authoring requires three three-quarter cover cells, but the image reads as two cover objects.
- The image still feels like a "color in the cube" treatment: the grid/control structure is too visible in the way the landscape is composed.

## Conclusion

This test confirms the direct image-edit route is not reliable enough for tactical combat map production. The method can produce attractive battlefield-like images, but it cannot currently preserve the full contract:

- exact authored footprints
- exact affordance count
- hidden grid rather than visible grid
- physically readable altitude
- no extra or missing tactical objects

For combat maps, the next viable direction should be deterministic geometry/rendering from the grid first, then stylization on top of that output. The core battlefield form needs to be generated by code or an engine, not inferred by image generation.
